## First measured finding: NXDN error-correction arithmetic

The soft convolution decoder used a constant complementary branch cost even
when the reliability weights changed. A punctured bit could therefore contribute
false evidence. The block-start operation also left survivor costs from the
previous independent block. The candidate uses exact complementary weighted
costs, resets each block, and retains costs in 32-bit storage. It does not change
encryption, synchronization thresholds, or channel settings.

| Independent experiment | 4.3.1 | Candidate |
| --- | ---: | ---: |
| Mathematical invariant cases passed | 1,245 / 1,952 | 1,952 / 1,952 |
| Exact known-payload blocks | 397 / 1,792 | 1,542 / 1,792 |
| Incorrect payload bits, out of 111,104 scored | 36,240 | 872 |
| Clean unpunctured and punctured blocks | 307 / 512 | 512 / 512 |

The independent encoder computes polynomial parity; expected payloads are not
generated by the decoder. Short-block exhaustive search checks minimum weighted
codeword cost, including ties and all 16 allowed initial histories. Full-length
SACCH/FACCH-shaped blocks use separate deterministic seeds. These code-block tests
omit CRC, sync, interleaving, I/Q and audio. Production also has CRC checks and a
hard fallback, so these rates **are not application RF failure rates**. Low-weight
corrupted bits are explicitly labeled by the test generator; real demodulator
confidence calibration remains unproven. There are still 250 incorrectly decoded
deliberately impaired candidate blocks, retained in the results.

The complete receiver then ran 76 input cases against both binaries: all 152
executions completed and all 16 mandatory clean/negative gates passed in each
variant. DMR/P25 observations and PCM remained unchanged. Eight impaired NXDN
cases changed. Seven produced additional frames, while the severe NXDN48 noise
case produced 12 fewer frames. Common frame payloads and error counters remained
identical in order. This is evidence of changed confirmation/gating, not proof
that every added frame is valid or intelligible. The same five non-gated field
recognition misses remain. The M17 fixture also produced identical PCM and
normalized diagnostic logs; its frame logger supplies no M17 payload records.

## Second experiment: preserve samples before a late detection

The standalone [IQ-history prototype](../../experiments/iq_history/README.md)
stores byte-exact CU8/CF32 samples with explicit stream identity, epoch, sample
rate, frequency, format and absolute sample intervals. Tests reject missing
intervals, stale epochs, overwritten data and arithmetic overflow. The retained
ring has a fixed capacity. This prototype is **not connected to live reception**.

Twenty-one successful test runs each included 7,000 ring/model comparisons plus
concurrency and discontinuity checks. Five isolated timing trials measured
median batch-average copies of 4.882 microseconds CU8 / 20.089 microseconds CF32
for 10 ms input blocks at 3.072 MS/s, and 0.593 / 2.505 ms for 250 ms snapshots.
These are desktop storage measurements, not decoder speed, worst-case latency,
or phone performance. Snapshot allocation/copy holds a mutex. Outstanding copies
are not yet globally bounded. Both issues must be addressed before live use.

The next prototype increment now adds a separate `CreditHistory` variant:
preallocated snapshot slots, a strict declared payload budget, explicit busy
results, and move-only ownership that remains valid after the history object is
destroyed. Both baseline and credit contract tests passed 20 repeated runs; the
credit test includes 1,600 parity cases plus exhaustion, lifetime and retune
checks. The original timing numbers above apply only to the original API.
The credit variant has not been timed; chunked copying and producer tail-latency
tests remain necessary. Payload limits do not include C++/allocator overhead.

## Third experiment: measure acquisition without inventing timestamps

The [source-sample timeline contract](SAMPLE-TIMELINE-CONTRACT.md) is implemented
as a benchmark-only validator with 45 deterministic tests. It preserves event
intervals and independent onset annotations, rejects missing or incompatible
lineage, exposes event loss, and invalidates later-stage claims when earlier
causal order is unproven. Recovery needs a valid preceding boundary. It does not
infer source positions from text logs or processed-audio counters. There is no
live instrumentation or new speed measurement yet. Source-sample delay and
wall-clock processing/audio delay remain explicitly different quantities.

| 4 | Calibrated separate soft-bit confidence improves NXDN/DMR decoding | Independent modulator and held-out messages; sweep noise, offsets, timing and overlap; score true bit/block errors and CRC false accepts | Improvement across held-out conditions without clean/negative regression; reliability cannot use oracle knowledge of corrupted positions |

| 6 | GPU batching helps only beyond a measurable workload size | Include transfer, launch, queue and synchronization costs; measure CPU/SIMD first; control background load and thermals | Better end-to-end p95 latency or throughput at equal quality, including integrated GPUs; no marketing claim from isolated kernel time |
| 7 | Selective warm reacquisition can recover faster without stale state | Timed dropouts/retunes and unrelated next calls across DMR, NXDN and P25; retain only proven-safe state | Earlier known-valid frame at equal false-call rate and bounded recovery; reset on incompatible stream/epoch |

The analytical sync-noise comment also required correction: the ordinary FSK
sync slicer has two output values, so its random-match model is not uniformly
four-ary. Thresholds remain unchanged. Full negative-control measurements take
precedence over an attractive theoretical probability.
